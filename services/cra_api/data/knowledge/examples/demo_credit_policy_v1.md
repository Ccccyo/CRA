# 演示授信规则 V1（完全模拟，历史版本）

> 样例元数据：`source_kind=mock`；`authority=demo_only`；`document_version=V1`；`effective_from=2026-01-01`；`effective_to=2026-09-30`；`region=ALL_DEMO`；`credit_segment=0001`；`status=staging`；`access_scope=demo_analyst`；`owner=演示项目维护者`。这不是任何真实公司的已批准制度。V1 参照当前 `credit_policy_mock.md` 的方向整理，恰好 250,000 美元的边界是演示拟定澄清，真实政策负责人未确认。

## DEMO-POL-V1-01 · 适用与责任

仅适用于模拟 CRA 信用分段 `0001` 的对外赊销评审，评审日自 2026-01-01 至 2026-09-30。模型可解释条款和起草，不得绑定主体、签署财务/风险意见、批准额度或改变服务端权限。经办分析师确认主体、财务证据和风险意见，独立高级分析师做最终复核。正式企业制度若另有规定，应退出演示决策并由政策负责人核实。

## DEMO-POL-V1-02 · 审批矩阵与偏离

申请额从案件 Excel `Executive Summary!B5` 读取，币种为美元：`≤ 250,000` 由区域信用主管审批；`> 250,000 且 ≤ 1,000,000` 由区域信用经理审批；`> 1,000,000` 由全球信用总监审批。原未版本化 mock 政策在恰好 250,000 美元处有重叠，不能反过来把本拟定边界当真实企业规则。

若申请额高于已验证的确定性建议额，应在 Risk Comments 写明两个金额、差额和理由，审批层级提高一级，最高为全球信用总监。若建议额、币种、已签财务输入缺失，不得判断是否满足升级条件。审批通过且在 SAP 生效之前不得向客户承诺额度；演示系统不连接真实 SAP。

## DEMO-POL-V1-03 · 财报有效性与例外

优先使用最近三个会计年度经审计的合并报表。管理层报表可提交人工评估，但 `Company Type` 不得选 `Private - audited`。最新报表期末距评审日**超过 18 个日历月**时标记过期并请求补充资料；恰好 18 个月不属于“超过”。合并范围、表头单位或 OCR 关键行未核清时暂停财务证据签署。金额、汇率与会计恒等式由结构化原件和程序核验，不由本规则卡生成。

## DEMO-POL-V1-04 · 风险意见、冲突和撤回

风险草稿分别检查偿债、杠杆、盈利、付款记录和国家背景，所有原子事实必须有可定位来源。历史审批仅供趋势参考；OECD 原表不自动映射为 CRA Sovereign Rating。发现错主体、错期间、数字冲突或两份同范围有效制度冲突时，列出冲突并交人工，不得给唯一审批建议。若 V1 已被撤回，可在解释历史评审时引用，但不得称为当前有效规则；新版本不得覆写其历史原件。
