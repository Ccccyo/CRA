# CRA 贸易赊销规则库＋证据库：30 份隔离样例

核查日期：2026-10-27。业务范围来自本项目 `PRODUCT.md`：卖方对 B2B 客户开展贸易赊销／客户信用额度评审，不是银行贷款。这里的 24 份规则卡和 6 份证据规范卡是**项目拟议控制**，不是 Dow 或其他公司的真实内部制度，也不是监管强制要求。没有真实客户资料或信用政策负责人签核；全部 `needs_human_review`、`is_published=false`。

## 构建逻辑

流程按“主体与申请 → 资料/财报 → 付款与敞口 → 外部背景 → 风险意见/授权 → 监控复审”拆解。每张卡回答一个可核查问题，包含拟议处理、必要证据、缺失/冲突处理、业务理由、待签核责任人和公开来源。这样检索到的卡不会只有抽象口号，也不会把同一规则的条件与例外切开。

逻辑上分为规则库（`CRA-R01`—`R24`）与证据库的“证据规范”（`CRA-E25`—`E30`）。后者**不是客户实际证据**；财报、SAP AR、外部报告和人工签署须在获授权后从案件系统/API读取并建立私有证据视图。金额、逾期天数、汇率、比率与额度比较由结构化数据和确定性代码处理。最终批额、停单和审批属于有权人员。

`catalog.json` 是30个独立文档记录的受控源，`scripts/build-rule-evidence-staging.py` 将其转为30个可引用的完整 Markdown 正文与30个片段，存入**单独** `services/cra_api/runtime/rule-evidence-staging.db`。保留一张卡一个片段是为了在首版确保主规则、所需证据和例外同时被召回；后续是否细分须以问答评测证明。

2026-10-27 更新：在用户允许模拟数据用于当前上线演示后，这30卡另以明确的“拟议·演示·未获政策签核”标签发布到在线 Neon 的 `CRA-DEMO-2026-10-24` 版本；原始 staging 库仍保持未发布。在线 Agent 仅对该版本的模拟案件开放 `proposed_rule` 与 `evidence_spec` 检索，正式制度问答仍只检索 `policy`；非模拟案件不能检索这些拟议卡。工作台展示两类只读知识空间。此变更只代表**演示可见**，不改变0卡获公司政策签核的结论。

发布由 `scripts/publish-demo-knowledge.py --apply-proposals-postgres --expected-host <精确主机> --expected-database <精确库名>` 完成；撤回用相同目标加 `--withdraw-proposals-postgres`。脚本只修改自身托管的30个文档，并保留审计日志。发布前后应分别检查文档/片段计数、标签、案件授权过滤、来源引用和回答边界；本次已验证30文档/30片段入库及模拟案件可检索，模型答案质量仍需按业务用例继续验收。

当前本地在线 Agent 健康检查显示 PostgreSQL 已连接，演示版本已启用；运行环境缺少向量/重排依赖，实际检索为关键词回退。仅验证了数据库读回、授权范围、检索命中与知识目录接口；未调用配置的外部模型做端到端回答测试，因此不宣称生成答案已通过业务验收，也不宣称已部署到公网生产环境。

## 来源分类与使用理由

| 来源 | 身份与合理用途 | 不能据此推出什么 |
|---|---|---|
| NACM 信用政策清单／信用报告文章 | 贸易信用实践：资料、额度、职责、催收、付款记录 | 本公司的额度阈值、签核权限或强制法律要求 |
| Allianz Trade、Atradius | 保险机构对买方评估、敞口和持续监控的专业实践 | 本公司保险合同、承保额度或自动批准规则 |
| GLEIF | LEI 和实体关系标识的官方说明 | SAP BP、DUNS 与 LEI 必然对应，或母公司自动承担子公司债务 |
| IFRS 10、IAS 7/8/21 | 相应 IFRS 报表的合并、现金流、重述和币种解释 | 所有客户都采用 IFRS；本公司的财务评分阈值 |
| D&B PAYDEX | 指标提供方对历史付款表现的定义 | 本公司实际AR、客户现时偿债能力或批准额度 |
| OECD 国家风险分类 | 官方支持出口信贷分类的原用途和限制 | CRA 客户级评级；OECD 明示不鼓励移作其他用途 |

来源网址及逐卡映射见 `catalog.json`。源网页是不断更新的资料，核查时应保存访问日、适用版本、许可与原文定位；IAS 21 当前引用的官方 PDF 为2022版，仅作方法参考，正式使用前须再次核对现行版本。外部报告的客户级内容未取得授权，本包没有抓取或复制。

## 审查结论与发布门槛

桌面审查结论见 `REVIEW.md`：30卡结构完整、来源可定位，适合**隔离开发/评测**；0卡获正式公司政策签核，不能作为真实客户审批依据。优先补正式信用政策与权限矩阵、CRA 21字段口径、材料门槛、SAP/AR与供应商数据契约、逐案件访问控制、版本/失效过滤和人工业务验收。入库成功只证明资料形态；还要分别测资料覆盖、授权检索命中、答案证据支持、冲突拒答和人工处置。
