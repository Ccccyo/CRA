# 风控视角桌面审查记录

审查日期：2026-10-27。审查性质：基于公开原始来源及CRA现有流程的**方法审查**，不代表持牌机构、真实公司的信用政策负责人、法务或财务负责人签署。结论仅允许隔离开发与明确标记的模拟案件演示使用，不允许用于真实客户授信。

## 判定准则

逐卡检查：对象是否是贸易赊销而非银行贷款；来源是否支撑所述方法而非被误称为强制政策；所需数据是否可定位；缺件/冲突是否不会被当作低风险；是否把精确计算与审批留给系统/人；外部数据是否标注许可、日期和范围。`C` 表示结构审查通过但仍待内部政策签核；`H` 表示另有明确资料/接口缺口；没有任何 `A`（正式批准）。

## 全包横向发现

1. **方法来源≠公司政策。** 13项公开来源均在 `catalog.json` 登记用途；24份规则都是项目推导的拟议控制，不能从NACM/保险机构文章推出本公司的阈值、权限或复审周期。
2. **会计准则有适用边界。** IFRS说明用于读懂采用IFRS的报表；其他会计准则、财年和新旧版次需另行核对。IAS21所引PDF为2022文本，须核现行版本。
3. **证据库还不是客户证据。** E25—E30是取得、保存和引用证据的规范；没有真实客户财报、AR、D&B报告或正式审批记录。
4. **高影响动作未授权。** 0卡包含可执行自动批准、调额、冻结、停单权限；这些应由服务端授权与人工签署执行。
5. **不能发布为正式制度。** 正式政策、材料门槛、字段字典、地域/生效日、逐案件权限、源许可与业务签核缺失。用户允许模拟数据用于当前演示后，这批卡已在 `CRA-DEMO-2026-10-24` 版本中以“拟议·演示·未获政策签核”身份单独发布；原始 staging 卡仍未发布。正式业务用途仍须独立评测与审批。

## 验证与下一道门槛

自动检查包括：30个唯一ID、24规则/6证据、每卡7项内容字段非空、来源ID全部可解析、隔离数据库30文档/30片段/0发布、重复构建0变更、拒绝写入`workbench.db`。这**不是**RAG命中率、答案准确率或风控效果评估。下一步请业务负责人至少抽审R01/R03/R04/R16/R20/R21/R22/R23及全部E卡，再用正常、错主体、过期报表、OCR冲突、逾期争议、版本冲突、无权访问和无答案案例做检索/回答验收；未过关仍留在隔离库。

补充检索抽查：隔离库的BM25对“OCR数字与原页冲突”“当前客户敞口和逾期”“谁能批准额度”“历史审批可否沿用”四个固定问法，首位均为对应卡（R10/R16/R21/E29）。首次抽查后，R21和E29补了业务常用问法；这只说明四条样例的词面检索可用，不代表同义问法、长问题、跨资料综合或答案引用合格。在线 Agent 的演示版本已能检索发布副本；非模拟案件和无演示版本时，权限过滤仍排除它们。在线模型回答质量尚未完成端到端验收。
