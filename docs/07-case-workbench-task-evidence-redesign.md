# 案件工作台“任务即证据”改造

## 1. 目标与边界

本次只改造案件详情页，不新建展示页、不更换设计系统、不改变现有 Agent 状态机。

核心原则：分析师点击「确认」前，必须在同一任务区看到被确认的完整内容、来源和影响。

保留：

- 顶部案件标题、状态、进度与五阶段条。
- 现有蓝、绿、黄、红语义色和组件规则。
- 人工关卡、Bad Case、RAG 引用、审计日志和案件问答能力。

不做：

- 不将执行日志伪装成 Agent 思考过程。
- 不让聊天面板直接改变案件状态。
- 不在没有原始证据时伪造生产结论。
- 不引入新路由或第二套 UI 组件库。

## 2. 信息架构

桌面端保留两栏，但责任重新划分：

1. **主工作区**：只显示当前阶段需要处理的材料、Agent 产物和主操作。
2. **右侧案件助手**：桌面端 sticky 固定，高度跟随可视区；消息区内部滚动，输入框永远可见。
3. **审计与案卷**：位于主工作区底部，默认收起。执行记录和通用证据不再与当前任务抢占首屏。

1280px 以下改为单栏，主工作区在前，案件助手在后；不用 fixed 遮挡手机内容。

## 3. 阶段专用工作台

### 3.1 企业主体确认

- 顶部显示 Excel/SAP 登记主体：客户名、BP、国家/城市、申请额度。
- 下方以对比表展示候选：选择、企业名与 DUNS、地址、匹配分、匹配理由。
- 未选候选时「确认主体」不可用。
- 确认时将 selected_entity_id 写入案件备注和人工责任记录。

### 3.2 财务证据签署

- 直接展示抽取表：字段、值、币种、报表期、原页、置信度、原文。
- 演示数据必须显示黄色警示，不与真实抽取混淆。
- 提供「下载抽取结果 CSV」，供分析师离线复核。
- 字段不足 21 个时显示缺失数，但是否允许签署由现有业务规则决定。

### 3.3 风险意见签署

- 先显示 Agent 生成的完整草稿：客户概况、财务观察、风险点、建议与人工复核提示。
- 草稿后直接显示本次 RAG 命中的来源列表，每条包含 namespace、标题、摘要与可见范围。
- 权限本期只展示元数据：「公开」或「信用分析师」；后续可在检索前加 role filter，无需改 UI 结构。

### 3.4 Excel 生成与最终复核

- write_workbook 阶段在主工作区显示「生成 Excel 新版本」主按钮。
- 生成后显示文件名、生成时间、版本原则和「下载 CRA Excel」按钮。
- 不向用户暴露服务器绝对路径；用「本案件 / 输出文件」表达存储位置。

## 4. 数据与接口最小改动

- 主体候选沿用现有 matcher 结果，在案件详情缺失时补齐可视数据。
- 人工任务解决接口保存 resolution，不再只记录「按过确认」。
- 新增财务证据 CSV 下载接口。
- RAG 来源增加 source_type 与 access_scope 元数据。
- Excel 生成后在案件备注保存 export_file_name 与 generated_at。
- 修正人工任务创建的参数错位，防止新关卡无法创建。

## 5. 方案审核

### 审核通过项

- **任务与证据同屏**：每个确认按钮都有明确的确认对象。
- **最小范围**：仅改案件详情组件和已有 API，不动 Landing、建案页和状态机。
- **不重复**：当前阶段数据只在工作台完整展示；案卷只提供总览和历史。
- **审计性**：所有原日志和证据仍可访问，但不再干扰当前操作。
- **权限可扩展**：RAG 来源已有可见范围展示位，后续可接 RBAC。
- **响应式**：固定聊天仅在宽屏启用，不遮挡窄屏主任务。

### 已排除的方案

- 为候选主体、财务证据、RAG 各建一个新页面：导航过重，不符合「最小改动」。
- 用弹窗承载完整表格：不利于对照和连续复核。
- 继续保留「通用证据卡 + 通用确认卡」：无法解决当前问题。

## 6. 开发方案与审核

开发顺序：

1. 补齐后端任务数据、resolution、CSV、RAG 权限元数据和输出文件元数据。
2. 建立 EntityReview、FinancialReview、RiskReview、WorkbookReview 四个阶段组件。
3. 将右侧案件助手改为独立 sticky rail，并把案卷收入折叠区。
4. 执行类型检查、Python 单测、API 验证和桌面/窄屏机械检测。

开发审核结论：

- 数据已存在 notes、task payload 和 event 中，无需改数据库 schema。
- 新增下载接口是只读操作，不扩大 Agent 权限。
- 四个阶段组件共享同一个任务容器，避免为每个阶段重复造页。
- sticky rail 不影响数据流，只调整布局，风险可控。

## 7. 验收标准

1. 主体关卡至少展示 1 条候选及其地址、分数和理由，确认结果被保存。
2. 财务关卡显示字段表，且 CSV 可下载、可打开、行数与界面一致。
3. 风险关卡同时显示草稿和 RAG 原文摘要，每条有来源类型与权限标签。
4. Excel 阶段有显式生成按钮；生成后显示文件名和下载按钮。
5. 执行日志和通用证据默认不占据任务首屏，但能一次展开查看。
6. 桌面端滚动页面时案件助手留在右侧，输入框一直可见。
7. 390px 窄屏无水平滚动，表格可在自身容器内横向滚动。
8. 不变更现有工作流阶段、人工关卡数量和 Bad Case 分级逻辑。
