# CRA 知识库数据搭建与结构化入库计划

> 2026-10-23；范围是卖方对企业客户的贸易赊销评审。本文描述首批开发/验证数据与后续正式资料要求，不声称取得真实公司政策或客户数据。RAG 回答不能替代结构化金额计算、服务端授权与人工审批。

## 1. 本轮实际落地与环境边界

- 本地隔离库：`services/cra_api/runtime/knowledge-staging.db`（SQLite）；使用项目已有 `knowledge_documents`/`knowledge_chunks` 结构。它**不连接**当前工作台，也不读取 `DATABASE_URL`。
- 远端隔离导入表：2026-10-23 已将同一清单同步到配置的 Neon PostgreSQL 中新建的 `cra_knowledge_import_document`、`cra_knowledge_import_chunk`。在线服务只读取 `cra_knowledge_document`、`cra_knowledge_chunk`，所以新增资料尚不可被在线 RAG 检索。同步脚本为 `scripts/sync-knowledge-import-postgres.py`，默认只做无连接预检；实际写入须显式传 `--apply --expected-host <主机> --expected-database <库名>`。本轮远端读回为 11 文档、51 片段、0 发布；重复同步改动 0 文档；在线表仍为 10 文档、197 片段。
- 来源登记：`services/cra_api/data/knowledge/examples/ingest_manifest.json`；构建：`services/cra_api/.venv/bin/python scripts/build-knowledge-staging.py`。原文、来源路径、SHA-256、版本、状态与片段均入库；相同原文及清单重复执行不重复写入。
- 当前 11 文档、51 片段，全部 `is_published=false`。两版制度与评分是纯模拟；CASE-003 是模拟案件；会计字段对照是待复核的项目整理；OECD、GLEIF、D&B、NACM 文件是项目对公开来源的简要摘录，**不是官方原件或客户查询结果**。OECD 的 `current` URL 会变化，不可把链接当不可变快照。
- 这里“所有数据”限定为 `ingest_manifest.json` 中已登记、已分级的 11 份**知识资料**；原始客户/案件文件、SAP 模拟 CSV、认证用户表、未核实的旧知识文件和二进制附件不因本次请求而批量导入知识表。它们各有结构化数据、授权和原件管理要求，不可混作 RAG 文本。现有运行时仅按 `library_id/case_id` 过滤，尚不会执行本库的状态、生效期、地域与 BP 标签；在服务端门禁实现前不得导入现有在线知识库或宣称权限安全。

## 3. 派生内容：何时生成，何时不生成

| 派生物 | 决定 | 约束 |
|---|---|---|
| FAQ | 暂不从模拟政策自动生成“真实制度 FAQ”；正式条款发布后可为高频问法编写 FAQ | 每条绑定条款 ID、版本、适用范围、负责人和原文；FAQ 不能修改规则含义 |
| 摘要 | 对长财报/制度可生成导航摘要；首批短规则不需要 | 摘要是派生索引，不替代原件；数字、条件、例外逐项回链并经人审 |
| 关键词/同义词 | 值得建立受控词表，如“授信额度/credit limit”、`DUNS`、字段英文名 | 原词保留；不得把申请额、建议额、批准额视为同义词；来自实际问法与字段字典，不造行业事实 |
| 问答对 | 用于开发/保留集评测，而非独立权威知识 | 现有 `rag_eval_cases.jsonl` 是设计金标草案，须映射真实 chunk ID 并核对；不能反向引用模型答案作为制度 |

## 4. 文档结构、切分、元数据与索引

**切分。** 当前首批仅处理经过人工整理的 Markdown。按 `##` 完整规则/证据卡切分，标题路径保留在片段正文与 `section`；示例表格的表头、单位、脚注与行保持在同一片段。单节过长时构建器拒绝重复条款 ID，不静默拆成无法独立解释的半条规则。未来 PDF/OCR 需保存源文件哈希、页图与页码，并在数字/表格复核后才发布。

**现已入库的文档与片段元数据。** `source_reference`、`source_kind`、`authority`、`status`、`is_published`、`content_hash`、`document_version`、`priority`、`owner`、`library_id`；按需要再带 `effective_from/to`、`region`、`credit_segment`、`case_id`、`bp`、`access_scope`、`source_url`、`source_as_of`、`verified_at`。片段另有稳定 `section_id`、`chunk_index`、`chunk_hash`、标题路径和原文 `citation`。缺失字段保持缺失，不推断为全球适用或无限有效。

**索引。** 隔离 SQLite 库建立 `library_id/status/region`、`case_id/bp` 和 `document_id/section` 索引。项目运行时已有中文分词 BM25；这批资料短、条款号和金额边界重要，先以授权 BM25 为基线。向量召回/重排仅在保留集证明同义问法确有漏召回且不损害边界题时采用，不用相似度替代适用性过滤。结构化 AR、额度与比率通过数据库/API 和确定性程序，不塞进静态全文索引当“实时值”。

**正式发布所需的服务端谓词。** 在检索**之前**由认证身份和受控案件关系决定可读范围：`is_published=true AND status='active' AND business_scope='trade_credit' AND applicable_as_of AND region/credit_segment match AND tenant match AND (case_id authorized OR allowed library)`。`case_history` 还需同 BP/显式授权；`case_evidence` 仅本案。撤回、版本替换、删除与权限变更须同步使索引和结果缓存失效。来源优先级不是固定的“官方 > 内部”：**内部批准政策支配本公司审批，官方标准解释其自身适用范围，供应商数据解释客户事实；跨用途冲突不可仅凭发布日期或检索分数决胜。**

## 5. RAG 运行、引用与可观测的后续契约

用户给出的 `{{retrieved_chunks}}` 等模板目前只是**待接线契约**，不是已经传入的真实片段。在线流程应先识别问题与案件、认证角色、选择评审时点；查询改写不得改金额/币种/否定；按服务端权限和有效期检索；对候选去重、冲突检查；回答逐个原子结论绑定 `document_id + chunk_id + source_position + version`。空结果、低相关、版本冲突、权限不足分开处理。检索文本只能作为证据，不能修改工具权限或审批边界。

问答完成后将 `intent`、原/改写查询、路由、候选与使用/丢弃的 chunk ID 及原因、知识/模型/Prompt 版本、权限判断、引用检查、缺口、失败与耗时写入**受限的服务端评估日志**，不把内部日志 JSON 默认拼给最终用户；敏感查询可存脱敏摘要/哈希，设置留存期。`confidence` 不能由模型自评充当事实正确率。项目当前引用检查仅验证编号及部分数字，语义支持需另评。

## 6. 验收与正式库发布门槛

本轮只验收数据搭建：11 文档/51 片段、全部未发布、来源哈希存在、CASE-003 有 `case_only` 标签、新增公开资料附官方 URL、21 字段表保持在同一片段、条款 ID 可定位、重复运行无额外写入。不得据此声称 RAG 命中率或回答质量。

下一阶段按 `rag_eval_cases.jsonl` 的 13 条用例，分别验证资料覆盖、检索命中、答案证据支持、权限拒答与异常阻断。正式库导入需要：政策所有者签署、原件和版本核对、服务端范围/有效期过滤、撤回与缓存失效、人工验收；缺任何一项时保持 staging。特别是模拟 V2 的 12 个月门槛不能作为真实企业制度发布。
