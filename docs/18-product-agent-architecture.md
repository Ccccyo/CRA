# CRA 产品与 Agent 架构（Demo 运行事实）

> 这是当前实现的简要产品说明，不把设计目标写成已上线能力。CRA Workbench 的定位是 SAP/SCASE 上游的授信审查准备与证据工作台，不替代 SAP 记账、额度主数据或最终审批。

## 1. 为什么做

SAP/SCASE 能保存客户、额度和审批结果，也能执行既定评分或流程，但真实授信审查仍要人工收集财报、确认主体、核对材料、解释风险并留下责任记录。产品解决的是“信息散、核对慢、依据难追溯”，而不是再造一个 SAP。

用户价值是把一份 CRA Excel 和财报转成可核对的案件包：主体、财务字段、风险意见、确定性评分、来源和人工签署在同一条链路中留痕，最后生成可交付 Excel。

## 2. 当前产品架构

```text
CRA Excel / 财报 PDF / 历史 SAP Mock / 版本化知识 / 可选外部来源
                         │
                         ▼
输入校验 → 主体人工确认 → 财报抽取与人工签署 → 检索与风险意见草稿
                         │
                         ▼
确定性评分与额度建议 → 回写 CRA Excel → 最终独立复核 → 交付
                         │
                         └── 案件帮助：只读问答、来源展示、拒答与 QA 升级
```

- **模型负责**：非结构化财报抽取、风险意见草稿、案件问答。
- **规则负责**：权限、状态流转、确定性评分、会计勾稽、数字与引用校验。
- **人工负责**：主体、财务证据、风险意见和最终额度四个责任节点。
- **数据隔离**：案件证据与共享知识分开检索；共享知识按 release 和有效期过滤。

## 3. MCP 在界面哪里

当前没有独立的 MCP 页面或“工具正在调用”面板。只读 GLEIF MCP 隐藏在案件详情右下角 **案件帮助 / 材料与规则查询** 中：用户明确输入一个 LEI 查询时，路由才会尝试调用，结果以外部来源出现在“查看本次回答依据”中。

当前限制：

- `CRA_ENABLE_GLEIF_MCP` 默认关闭；关闭时会明确告知未启用实时查询。
- 只查法律实体名称、注册状态、国家、更新时间和原始链接。
- 不证明该实体就是 SAP BP，也不提供信用评级或审批结论。
- 不写回案件或 SAP；外部数据仅作为待人工核验的补充证据。

建议的最小产品补齐是在案件材料区增加“外部数据”卡片，展示提供方、查询参数、查询时间、状态和刷新入口；不需要为 MCP 单独做一个复杂管理后台。

## 4. Skill 与 Harness 的真实状态

### Skill

项目有开发侧的 `cra-risk-opinion-draft` Skill，用来约束风险意见的证据、缺失材料、规则版本和人工签署边界。它目前是 Codex/开发流程资产，不是 Web 运行时对每个案件动态加载的 Skill。线上案件使用的是后端代码、Prompt 和校验器。

### Harness

当前属于“部分 Harness 化”，已有固定状态机、角色权限、人工门禁、内容哈希签署、来源校验、失败转 QA/Bad Case 和事件日志。尚未完成统一的 run/step/operation/attempt 账本、进程中断恢复、未知结果对账、全局预算/超时和生产级 Prompt/工具注册回滚，因此不能宣称已建成完整企业 Agent Runtime。

## 5. 每个案件的对话能力

案件帮助每次只在当前用户有权访问的案件和已发布共享资料中检索，支持：

- 解释案件为什么停在当前节点、下一步由谁确认；
- 查询案件已使用的证据、财务字段、规则和流程；
- 回答 SAP/SCASE/CRA 流程问题；
- 在明确 LEI 且开关启用时查询 GLEIF；
- 对答案引用和数字做程序校验，失败时扩展检索重写一次，仍失败则拒答并创建 QA 任务。

边界：它不能审批额度、改变角色或工作流、写入 SAP、提供未连接的实时敞口，也没有跨刷新保存的长期对话记忆。当前仅向模型提供最近两轮可信消息，避免无边界上下文污染。

## 6. Demo 财报情景

输入 CRA 模板的“本期财报”保持空白是有意设计：本期数据应在上传财报、抽取和人工签署后回填。没有正式财报时，用户可载入明确标注的模拟当期财报。

模拟情景使用不同业务驱动，不再把所有科目统一增长：收入增长 4.0%，成本增长 3.5%，应收与存货低于收入增速，短期和长期借款下降，经营现金流增长 10%，资本开支增长 8%。其他资产和负债温和延展，总资产、总负债与所有者权益由组件重新计算并强制满足 `资产 = 负债 + 权益`。

这些数字用于演示“抽取—核对—签署—评分—回写”的产品流程，不是对真实客户的预测，也不能用于真实授信决策。
