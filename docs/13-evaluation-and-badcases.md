# CRA 评测体系与首轮 Bad Case（模拟演示环境）

## 1. 范围和责任边界

本轮评测对象是 **B2B 贸易信用评审辅助流程**，不是贷款审批，也不是金融机构生产适用性认证。项目可以帮助识别主体、核对财报、查阅制度/外部资料、起草风险意见和回填 Excel；额度、例外和签核仍由有权人员完成。题库中的制度、客户财报和历史审批均为**模拟材料**；GLEIF 等公开资料应按来源、日期和用途限制使用。

评测分五层，不能用其中一层代替另一层：

| 层 | 最小可观察结果 | 评分与证据 | 当前状态 |
|---|---|---|---|
| 资料 | 题目所需的每个金标章节存在、已发布、在评审日和案件权限内可用 | 金标章节 / 发布元数据 / 版本 | 已有离线检查；真实制度待取得 |
| 检索 | 候选前 20 和最终前 8 覆盖必要证据；保留顺序和 ID | 逐章节召回与逐题完整证据率 | 本轮已实测 BM25 演示发布集 |
| 生成 | 原子结论被所引证据支持；数字、币种、期间、否定与适用边界正确；该补问/拒答时不硬答 | 规则断言 + 业务专家盲审；不能只看文本包含词 | 未实测，不计入检索分数 |
| 执行与权限 | 越权案件在检索前阻断；不自动审批、签署或用历史决定替代现行规则 | API 授权测试、状态和审计记录 | 部分单测已有；在线端到端待测 |
| 业务结果 | 人工能核查来源、处理异常并正确完成签核/Excel 回填 | 人工评审、回填重开核对、耗时与返工 | 待业务评审；模拟结果不能外推真实业务 |

金标由业务负责人确认，开发者维护测试执行。开发集可用于调试，holdout 仅用于阶段验收；修改规则时先复核金标。`rag_eval_cases.jsonl` 的 13 条只是起步样本，不能推断总体准确率或线上风险为零。

## 2. 可运行基线和统计口径

运行：

```bash
services/cra_api/.venv/bin/python scripts/evaluate-cra-rag.py --output services/cra_api/eval/reports/demo-rag-baseline-2026-10-26.json
services/cra_api/.venv/bin/python -m pytest services/cra_api/tests/test_rag_evaluation.py -q
```

评测脚本只读取 `publish-demo-knowledge.py` 的**当前演示发布白名单**和 `rag_eval_cases.jsonl`，不连接数据库、不调用 LLM、不执行审批。它记录发布集 SHA-256、release ID、逐题金标、实际 Top-K、各阶段漏失及首个失败环节。摘要分母固定为 9 条可评分题 / 22 个金标章节；4 条未评分题仍显示在清单中。`gold_recall_at_k_over_all` 的分母包括发布集中缺失的金标，`gold_recall_at_k_over_available` 只包括通过当前范围过滤的金标；两者都不是全库真实召回率。`complete_evidence_case_rate` 要求一题的**全部**金标进入 Top-K，不是命中任意一段。

2026-10-26 本地基线（已运行；仅模拟发布集、离线 BM25、无生成）：

| 项 | 实测 |
|---|---:|
| 演示文档 / 片段 | 5 / 24 |
| 题库 / 可评分 / 未评分 | 13 / 9 / 4 |
| 金标在发布集内 | 19/22（86.36%） |
| 可用金标在候选前 20 | 15/19（78.95%） |
| 金标进入最终前 8 | 13/22（59.09%）；按可用金标为 13/19（68.42%） |
| 全部必要证据均到齐的题 | 4/9（44.44%） |

当前检索证据门槛**未通过**。这不是生成答案准确率、拒答率或线上权限测试。向量与重排依赖未安装，本次没有比较它们，不能声称混合检索的效果。

## 3. 首轮 Bad Case 归因

| ID | 首个失败环节 | 证据与风险 | 最小修复及同条件复测 |
|---|---|---|---|
| KR-02（holdout） | 候选召回 | “六十万美金”未召回模拟审批矩阵；只找到无关 GLEIF 主体章节。金额同义表达失配，可能错答签核人。 | 在不改 holdout 金标的前提下，用开发题增加受控金额/币种归一化；重跑全题，检查数字与单位不被改写。 |
| KR-06（holdout） | 候选召回 | OCR 原页与抽取冲突片段已出现，但“不得自动选数/财务阻断”条款未进候选。若只看两数，可能遗漏处理规则。 | 对该规则设计明确的业务路由或受控查询扩展；保留 214,000/241,000 千 MXN 与原页。复测跨段完整证据。 |
| KR-07（holdout） | 资料缺失；且可用资料也漏召回 | OECD-CRC-02 未在五文档发布集；未审计/付款/国家背景综合题另外漏了两个可用证据。不能生成完整可引用的综合意见。 | 先审查公开资料版本/许可/出处后决定是否发布；再测多子查询汇总与证据去重。不得用旧公开资料替代金标。 |
| KR-08（dev） | 资料缺失 | 两个 OECD 金标均未发布。现有片段无权支持“- 等于 0”或 CRA A 档的判断。 | 审核并发布有日期的官方资料及内部映射说明；没有内部映射时明确拒绝自动定档。 |
| KR-09（holdout） | 候选召回 | 审批条款命中，但模拟历史批复及其条件均未召回；有把“去年 44 万”误当本次可续批依据的风险。 | 将历史检索按 BP/案件范围独立召回后与现行制度合并；验证历史只作证据、不变成本次规则。 |
| KR-10 / KR-13 | 未安装注入 fixture | 同范围规则冲突和文档提示注入未执行，不能当作通过。 | 在隔离测试库安装冲突与恶意备注，断言暂停唯一结论、权限与签署状态不变。 |
| KR-11 / KR-12 | 无答案/权限题未测生成及在线授权 | 检索可返回无关片段，不代表最终会拒答；KR-11 还需前门案件权限验证。 | 分别以授权用户/无权限用户走 API；核对检索上下文、最终答复和审计日志无跨案泄露。 |

优先级：权限/自动批准与规则冲突为 **P0 发布阻断**；资料缺失、关键证据漏召回及错误引用为 **P1**；表达形式、延迟和非关键背景为 **P2**。上表是失败证据及根因假设，不把假设写成已证实的代码缺陷。每次修复在报告中保留版本、输入、金标、实际片段、首错节点、变更和复测结果，不能只记录“已解决”。

## 4. 下一轮验收设计

1. **检索门槛**：演示关键题所需章节全部已发布且适用；关键规则题全部进入最终上下文；按 dev/holdout 与场景分别报告，不以整体均值掩盖局部失败。这个目标是发布门槛，不是本次实测结果。
2. **生成门槛**：对每题逐条标注原子结论、必要出处与禁止表述。精确值/比较符/币种/日期/引用 ID 用程序校验；语义支持和业务边界由业务专家复核。对无答案、冲突、过期、越权分别统计正确拒答与误拒答。模型评委只作辅助，人工抽查争议项。
3. **Agent 端到端**：至少跑正常案例、OCR 数值冲突、无当前 SAP AR、历史审批与当前政策冲突、跨案无权限、注入备注、导出后重开 Excel 七类。记录意图和对象识别、工具参数、检索证据、草稿、人工节点、最终业务状态，定位**首个**错误。
4. **观察与回归**：日志关联 case ID、用户角色、知识版本、模型/Prompt 版本、检索策略、候选及最终 chunk ID、引用校验结果、人工纠正与延迟；日志中的敏感原文应脱敏并遵守权限。已核实 bad case 入回归集，旧题不能因修复而退化。
5. **发布规则**：任何 P0、关键规则无证据却肯定作答、跨案泄露、自动批准或签核均阻断发布；P1 需修复或限定演示范围并明确告知。真实客户与正式制度尚未验证时，仅能声明“模拟演示可用”，不能声明生产授信可用。

后续需要取得：经批准的正式授信政策及版本、财务字段映射/单位口径、材料与异常规则、授权脱敏的付款/历史数据、外部资料使用许可与映射说明，以及业务专家对金标和风险意见的复核记录。缺少这些资料时，线上评测只能验证模拟流程及技术边界。
