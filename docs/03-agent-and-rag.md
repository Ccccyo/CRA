# Agent 与 RAG 实施说明

> 文档角色：本文件只描述当前实现和工程排障，不重新定义产品需求。Agent、Prompt、工具、RAG、Harness 和 Bad Case 的唯一产品口径见 `PRODUCT.md` 第 4–7、11 节；能力完成状态见 `docs/16-capability-status.md`。

## 1. 统一状态机映射

所有界面、API、日志和评测统一使用以下节点 ID：

| 顺序 | 节点 ID | 当前主要实现 | 人工门禁 |
|---|---|---|---|
| 0 | `intake_excel` | Excel 解析、模板与重复案件检查 | 建案确认/更正 |
| 1 | `resolve_entity` | 规则型主体候选 | 主体确认 |
| 2 | `financial_evidence` | 财报抽取与确定性校验 | error 关闭、warning 处理 |
| 3 | `financial_signoff` | 对象版本与内容指纹签署 | 财务证据签署 |
| 4 | `retrieve_context` | 授权知识与案件证据检索 | 无证据/冲突时转人工 |
| 5 | `risk_signoff` | 风险草稿、引用校验与签署 | 风险意见签署 |
| 6 | `external_score` | 确定性模拟评分、额度方法和审批分级 | 正式规则缺失时阻断 |
| 7 | `write_workbook` | 财务字段、`AI Import`、意见和评分回写 | 重开与内容校验和核验 |
| 8 | `final_signoff` | 额度、偏离、审批和 artifact 复核 | 独立高级分析师签署 |
| 9 | `completed` | 当前有效版本锁定与历史保留 | 无 |

当前模拟主流程为 `risk_signoff → external_score → write_workbook → final_signoff → completed`。旧文档中的 `ingest_report`、`extract_financials`、`validate_financials` 和 `draft_risk` 仅作为节点内部子步骤，不再作为顶层服务路径名称。

## 2. Agent 运行边界

核心信用评审采用固定 Workflow；模型负责非结构化抽取、受控 query 改写、证据组织和草稿生成，不决定权限、额度、审批层级、签署或状态推进。系统每次读取最新案件版本，计算唯一允许的下一步，调用白名单工具，验证结果，再选择通过、有限重试、阻断或转人工。

当前已有固定状态机、人工任务、内容指纹签署、签署失效和 artifact 核验；统一 `workflow_run/step/operation` 账本、进程中断恢复和生产迁移仍是 P0 待交付。预算、超时、重试、恢复和上下文策略统一见 `PRODUCT.md` 第 7 节，不在本文件复制。

## 3. RAG 当前实现事实

### 3.1 知识空间

| 空间 | 当前用途 | 约束 |
|---|---|---|
| `policy` | 内部政策、评分规则、字段口径 | 当前有效版本优先；模拟政策持续标识 |
| `public_reference` | 国家、行业、会计和公开身份资料 | 只作背景或释义 |
| `case_history` | 已完成同 BP 历史评审 | 只作类比，不复用审批结论 |
| `case_evidence` | 当前案件 Excel、财报、外部报告和人工记录 | 隐藏空间，仅当前授权案件可读 |

结构化金额、签署、评分和工作流状态来自数据库或确定性工具，不从 RAG 文本还原。

### 3.2 在线链路

```text
校验用户与案件权限
→ 识别对象、时间和业务口径
→ 必要时受控改写
→ 按案件/角色/版本/有效期过滤
→ 检索与排序
→ 组织证据
→ 生成草稿或回答
→ 校验引用、数字、适用期和权限
→ 返回 / 受控重写 / 转人工
```

当前实现具备 BM25，并包含向量、融合和重排的底层能力；实际是否启用以 `/health.rag` 为准。当前版本化基线只证明隔离环境中的检索表现，生成、拒答、冲突、注入和生产权限需要独立评测。具体结果只记录在版本化评测报告和 `docs/16-capability-status.md`，不在多份文档重复数字。

### 3.3 写入、更新与撤回

管理员上传后，服务端校验权限与文件，保存原件和完整正文，生成检索片段，并在同一文档版本内维护内容指纹。文档编辑、删除、撤回或权限变化必须同步影响片段、向量项和缓存；失败不能留下半发布状态。

正式知识发布生命周期、权威性、适用期、冲突和撤回规则见 `PRODUCT.md` 第 6.4 节；知识内容和验收细节见 `docs/10-rag-knowledge-design.md`；隔离数据构建记录见 `docs/11-knowledge-data-build-plan.md`。

## 4. 风险意见与案件问答

**风险意见**：根据已签案件事实构造检索问题，在授权范围内取得证据，生成结构化草稿，并校验引用、数字和选项。模型不可用或校验失败时使用带引用的受控降级稿，最终由分析师签署。

**案件问答**：分别检索本案证据和共享知识，只把相关片段发送给模型。第一次校验失败可按策略重写；仍失败时不返回未经校验文本，创建人工复核和 Bad Case。客户端不能注入 system/tool 历史角色。

## 5. 权限与信任边界

- 浏览器经 Next.js 代理访问 FastAPI，前后端均校验角色；
- 数据库读取、检索候选和文件下载前都必须执行案件 ACL；
- 文档、Excel、历史备注和检索片段一律视为数据，不能改变权限、工具范围或签署规则；
- tenant/region 元数据已保存，但可信身份 claim 尚未接入，不能宣称完整多租户隔离；
- 内部现行政策优先于公开背景和历史经验；客户事实以当前案件原件和结构化快照为准。

## 6. 工程排障顺序

1. **状态不一致**：核对 `current_stage`、人工任务、有效签署和依赖版本；
2. **目录/文档不可见**：核对角色、案件关系、知识状态和文档 ID；
3. **检索不到**：核对 `/health.rag`、空间/案件过滤、知识版本和 query；
4. **引用或数字失败**：查看生成校验、重写结果、人工任务和 Bad Case；
5. **Excel 不一致**：核对已签快照、回写报告、重开结果和 artifact 内容校验和；
6. **结果未知**：先对账数据库、operation 和 artifact，禁止直接重放高影响写入。
