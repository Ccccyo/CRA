# CRA 知识内容、治理与 RAG 验收设计

状态：设计稿；2026-10-23 核对仓库代码和资料。适用于现有本地演示工作台，不代表 Acme Chemical 或任何真实公司的制度。此文档不改变检索代码或生产知识库。

## 1. 业务任务与知识需求对应表

现有入口是 SAP/VBA 预填的 CRA Excel；演示系统没有生产 SAP、D&B、SCASE 连接。信用分析师办理主体、财务证据、定性风险，独立的高级分析师做最终复核；管理员维护知识源。现有程序按固定阶段推进，知识只能支持理解、解释和草拟，不能替代绑定主体、精确计算或签署。依据：`PRODUCT.md`、`docs/01-product-flow.md`、`cra_api/main.py`、`cra/draft/narrative.py`。

| 用户 / 场景与具体问题 | 必需知识与关键判断 | 应取自其他通道 | 缺失时的结果 |
|---|---|---|---|
| 分析师建案：“这个 BP 的历史评审和本次申请有什么变化？” | 历史评审摘要、当时适用规则和偏离理由；仅供比较 | 本次 BP、额度、期间和 Excel 原始快照；历史审批记录的结构化查询 | 说明没有可比历史，不把别家历史当本案先例 |
| 分析师认公司：“Harbor Polymer 的哪一个 DUNS 对应开票主体？” | 模拟 Lookup 操作说明、名称/地址/母子公司识别指南、标识符释义 | BP 与地址来自 Excel；候选来自 D&B 模拟数据或获授权实时接口；匹配分由代码计算 | 同名/地址冲突时人工确认；不得凭 RAG 文本 Merge |
| 分析师读财报：“2025 存货应取哪列、什么单位、是否合并？” | CRA 字段定义、报表术语映射、合并范围和 OCR 异常处理说明 | 客户 PDF 原页和财报期间；抽取值、倍率、会计恒等式由程序处理 | OCR 与原页不一致或报表范围不明时停止财务签署并补件/复核 |
| 分析师问规则：“60 万美元由谁审批？最新财报过期了吗？” | 有效的审批矩阵、财报有效性规则、适用地区/额度/日期、例外路径 | 申请额度、评审日期、财报期由案件结构化字段提供；阈值比较由代码执行 | 制度未获正式确认、边界歧义或过期时不下审批结论，交政策负责人 |
| 分析师起草风险意见：“墨西哥客户偿债、付款与国家背景有何风险？” | 风险意见规范、字段口径、D&B 指标释义、OECD 背景、同 BP 历史理由 | 财务指标、SAP AR、D&B 客户报告、当前评分来自结构化快照/接口；比率和额度由确定性程序计算 | 某维证据缺失则写“材料不足”；不得凭行业均值补客户数字 |
| 高级分析师复核：“申请额高于建议额，是否满足偏离和签署要求？” | 当前审批/偏离规则、例外处置记录、反证和版本说明 | 建议额/风险级别来自模拟评分或未来 SAP；签署状态和操作者来自数据库 | 规则或建议额未确认时维持待复核，不自动批准 |
| 管理员维护：“新制度上线后旧条款还能被引用吗？” | 政策发布记录、废止清单、来源责任人、变更说明 | 文档/片段状态、权限、索引和缓存版本由系统维护 | 未完成撤回同步时暂停受影响规则问答 |

RAG 适合提取非结构化条文、字段解释、原页叙述和有上下文的历史理由。BP、DUNS、金额、当前状态、汇率、评分、额度、权限、有效期比较优先来自数据库/API/确定性计算。用户补充只能成为待核事实，不能直接升格为政策。

## 3. 知识分类、来源和资料清单

逻辑上按判断对象分类；物理上沿用 `policy`、`public_reference`、`case_history`、隐藏的 `case_evidence` 四个空间及共享检索器。前三者可在阅读界面呈现完整原文；案件证据由 `case_id` 隔离。分类不等于四套独立向量库：现阶段共享索引加检索前强制过滤足够，只有多租户法律隔离、数据驻留或实测性能要求才考虑独立索引。独立索引也不能替代数据库权限。

### 3.1 授信政策、审批与操作规范（`policy`）

- 任务：审批层级、复审周期、财报新鲜度、定性选项、偏离与人工责任；避免错用旧阈值或把建议当批准。
- 内容/字段：条款 ID、规则条件及比较符、例外与禁止事项、适用法人/国家/信用分段/客户类型、审批角色、流程动作、依据文件、发布人、版本、`effective_from/to`、`supersedes`、发布日期、撤回状态、保密级别。
- 来源/可用条件：未来正式政策须由信用政策负责人提供签署版和发布记录；当前 `credit_policy_mock.md`、`cra_scoring_rules_mock.md`、`faq_mock.md`、`dnb_api_guide_mock.md` 只限演示。技术操作说明需系统所有者校准。
- 更新/责任/权限：政策发布即触发更新，至少每季度核对目录；政策负责人批准，知识管理员入库，分析师按角色只读。地区限制应细化到源/片段。
- 失败：未获批准、超有效期、边界重叠或两份有效文件冲突时，回答可说明已知部分与冲突位置，但不得确定审批级别；提交政策负责人，待解冲突材料不参与自动草稿的规范性结论。

### 3.2 字段口径、财报阅读和 Excel 交接（`policy` 的内部口径 + `public_reference` 的准则释义）

- 任务：21 字段、合并/母公司、期间、单位、重述、字段缺失、Excel 格式；防止错列、错单位和错来源。
- 内容/字段：CRA 字段键、显示名、同义词/标准元素、报表类型、单位/币种、允许空值、优先位置、不可替代字段、适用模板版本/会计准则/年度、实例页码、负责人。
- 来源/可用条件：内部 Excel 模板与经批准字段字典决定交接口径；`accounting_field_definitions.md` 是公开概念整理，须逐条复核。美国上市公司申报/XBRL 可通过 [SEC EDGAR API](https://www.sec.gov/search-filings/edgar-application-programming-interfaces) 获取，但 XBRL 标签不能代替客户原始财报；IFRS 18 对 2027-01-01 或以后开始的年度报告期间生效，允许提前适用，不能默认套到 2025 报表（[IFRS 官方](https://www.ifrs.org/issued-standards/list-of-standards/ifrs-18-presentation-and-disclosure-in-financial-statements/)）。
- 更新/责任/权限：模板或会计口径变更即更新；财务方法负责人审核，管理员发布；客户财报原页仅案件授权人员可读。
- 失败：页码、表头、单位、合并范围或重述不清时保留 `unknown` 并请求财务人工核验；金额换算与资产负债平衡由代码处理，不由检索片段估算。

### 3.3 本案非结构化证据（`case_evidence`）

- 任务：解释本案主体、财报来源、人工修改和风险草稿的证据链；缺失会造成错客户、错期和不可追溯数字。
- 内容/字段：`case_id`、BP、源文件哈希、文件类型、原文页码/表格行/Excel 单元格、抽取原值及单位、结构化值 ID、复核状态、记录时间、版本、签署状态；同页冲突要并列保留原文和抽取结果。
- 来源/可用条件：本案 Excel/PDF、获授权的 D&B 报告和 SAP 交接、分析师复核记录；演示均标 `MOCK`。从结构化快照生成的“证据视图”只是索引，不是原件。
- 更新/责任/权限：源文件或人工确认改变即重建受影响视图并使旧签署/派生结果失效（目标，现有实现尚不完整）；案件负责人确认，系统维护索引；仅本案授权人员可读。
- 失败：原件不可访问、版本错位或抽取值不等于原页时停止相关草稿结论和财务签署，转人工核验；不得从其他案件补数。

### 3.4 历史评审与处置经验（`case_history`）

- 任务：同 BP 趋势、此前例外理由与复审条件；缺失会使风险变化缺乏纵向解释。
- 内容/字段：BP/DUNS、评审周期、财报期、申请/建议/批准额、币种、风险级别、适用规则版本、审批结论及理由、撤销/更正状态、原审批单引用、访问范围。跨客户教学案例需脱敏 ID 与重识别风险审查。
- 来源/可用条件：未来 SAP CRA/SCASE 批准记录；目前 `cra_submissions_mock.csv` 是纯模拟，不作真实先例。
- 更新/责任/权限：审批终态或更正时同步；信用运营负责人确认；本案比较默认同 BP，跨客户检索需要额外授权和脱敏。
- 失败：历史结论与现行政策冲突时保留“当时审批”描述，不当成当前规定；没有批准记录就不说“过去批准过”。

### 3.5 外部企业识别和评级释义（`public_reference`，客户报告在本案）

- 任务：名称/注册地址/母子关系辅助核验；解释 PAYDEX、评级或失败分的含义，避免混同本公司 AR 付款习惯。
- 内容/字段：供应商、产品/地域、标识符、登记名称、地址、母子关系、记录状态、抓取时间、指标定义、分数尺度、版本与许可条件。实际 DUNS、评分和更新时间应保存在结构化供应商结果，不写成通用政策。
- 来源/可用条件：[GLEIF LEI 数据](https://www.gleif.org/en/lei-data/gleif-concatenated-file/download-the-concatenated-file) 可辅助“谁是谁/谁拥有谁”，但 LEI 记录状态和主体关系需要核实；[D&B PAYDEX 官方释义](https://www.dnb.com/en-us/smb/resources/credit-scores/what-is-paydex-score.html) 与获授权产品文档说明含义，实际报告依许可证和供应商权限使用。模拟 Lookup 的 `CONF_CODE`、错误码不是 D&B 真实接口规范。
- 更新/责任/权限：供应商版本变更即核对，概念说明至少半年复核；外部数据负责人和合规/采购确认许可；个体报告按案件权限。
- 失败：同名候选或两个源地址冲突时展示差异并人工绑定；无评级不等于低风险，未确认主体不得引用其评分。

### 3.6 国家与行业背景（`public_reference`）

- 任务：解释国家转移/兑换风险和可比企业范围，为意见提供背景；缺失时只对客户直接证据作分析。
- 内容/字段：国家 ISO3、OECD 类别、来源快照日期与页、未分类脚注、地域；同行名单/CIK、行业分组、财年、会计准则、指标公式、样本量、分位数和排除规则。
- 来源/可用条件：[OECD 官方分类](https://www.oecd.org/en/topics/sub-issues/country-risk-classification.html) 用于官方支持出口信贷风险分类，OECD 明示不鼓励移用于其他用途；若 CRA 使用，须由内部政策明确映射。[2026-10-16 当前原表](https://www.oecd.org/content/dam/oecd/en/topics/policy-sub-issues/country-risk-classification/cre-crc-current-english.pdf) 中墨西哥为 3、美国为未分类 `-`。美国上市公司同行数据可取 [SEC EDGAR](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)，需标记期间和可比性。
- 更新/责任/权限：OECD 每次发布核对并保留快照，PDF、结构化 CSV、说明和 `oecd_risk_text` 所用日期须同步；行业对标至少每个财年重算。研究/风险方法负责人审核；可公开阅读，但内部映射仍属政策权限。
- 失败：外部源过期、国家缺值或不具可比性时只说明数据缺口；不得把 `-` 当 0，也不能自动给 CRA Sovereign Rating。

## 4. 核心知识内容样例

`services/cra_api/data/knowledge/examples/` 提供四份完整内容样例及机器可读评测集：

1. `demo_credit_policy_v1.md` 与 `demo_credit_policy_v2.md`：两份独立文档级版本的纯模拟授信条款，含生效范围、审批边界、财报年龄、冲突处理、人工责任。V2 是为了验证版本切换而设计的假设，不是现有公司的制度变更。
2. `demo_case_003_evidence.md`：从仓库 `CASE-003`、模拟 OCR 和历史 CSV 整理的案件证据；明确“241,000 vs 214,000”冲突、单位、未审计/合并范围未知和不可签署状态。
3. `oecd_2026-10-16_reference.md`：真实公开资料的有限摘录与用途限制，不能自动成为公司评分规则。
4. `demo_case_003_history.md`：从模拟历史申报提取的两次复审及批准理由；只说明当时处理，不给当前审批依据。

样例可直接用于解析、检索、引用与拒答联调，但位于子目录，当前 `load_markdown_dir(.../*.md)` 与一次性 `knowledge-seed-v2` 不会自动将它们装入在线库。管理员须审核、选定用途和元数据后手动导入测试环境；特别不得把两版模拟政策与未版本化 `credit_policy_mock.md` 同时作为“有效政策”。

## 5. 入库、检索、权限和更新设计

**入库门禁。** 建议源资料状态为 `draft → reviewed → active → superseded/withdrawn`。先登记来源 URL/文件、原件 SHA-256、权威级别、许可、维护人和 `observed_at`；解析后由责任人看完整正文、表头、脚注、页码和 OCR 低置信片段。只发布 `active` 且当前用户/案件允许的资料。当前上传 API 直接入库，没有发布门禁；这是实施任务，不应在本轮假称已具备。

**切分。** 政策按“条款 ID + 适用条件 + 主规则 + 例外 + 禁止 + 生效”组成原子决策卡；FAQ 保持问答成对；财报按“报表名/合并范围/币种单位/期间表头 + 行 + 脚注”成组，必要时引用父页；历史一次评审一段但保留审批结果和当时政策版本；OECD 表行连同列名和脚注。现有 Markdown 约 800 字符、PDF 约 1000 字符的通用切分可能断开表头/例外，须用上述样例比较后确定实际块长，不把固定字符数当业务边界。OCR 数字须与原页逐项核对。

**最少元数据。** `document_id`、`chunk_id`（稳定 ID）、`logical_type`、`library_id`、`source_kind`（official/internal/mock/case）、`authority`、`source_uri/object_key`、`sha256`、`publisher/owner`、`tenant`、`region`、`credit_segment`、`case_id/BP`、`document_version`、`effective_from/to`、`published_at`、`observed_at`、`status`、`access_scope`、`parser_version`、`section_path`、`page/table/row/cell`、`supersedes`。业务金额另有结构化值 ID 和期间，不只埋在 chunk 文本。必需字段缺失则不可发布为规范性知识。

**去重、冲突、撤回。** 相同 SHA-256 只存一份原件，可有不同授权视图；同一条款的新版本建立继承关系，不覆写旧版。查询用评审日 `as_of` 选版本；同一日期的两个有效且同范围条款冲突时阻断该结论并留冲突工单。撤回应先把状态改为不可检索，再删除/重建 chunk、向量项和查询缓存；保留受限审计快照及已经形成的历史引用，不允许旧引用被重新解释成当前有效政策。当前删除 API 能删文档/chunk 并记录日志，但缺有效期过滤与多实例失效确认。

**在线路由和排序。** 先识别对象、日期、任务和可用数据源。额度/状态/客户指标走结构化查询；条款与背景走授权 RAG。检索前按角色、租户、案件、地区、生效时间、状态过滤；原 query 保留，专有名词和数值不随意改写。BM25 先作基线，政策条款优先同范围的最新有效版本；公开资料和历史材料可作辅助但不能覆盖政策。对每个原子主张保留 source、version、section/page、as-of、原文片段，点击可回到完整原件。引用 ID/数字校验后还需检查适用条件和语义支持。

**是否升级检索。** 现有关键词法已能命中明确术语、错误码和若干制度问法；首要风险是资料权威、版本、原页证据与语义校验。只有在标注集显示跨语言/同义问法在授权 BM25 中漏召回时，比较现有 BGE-M3、混合与重排，报告 chunk 级 Recall@5/20、正确引用、P0 错误、p95、内存和冷启动。重排无法补回未召回的条款。提升不足或成本明显时保留 BM25。

**不可信资料。** PDF、Excel、历史备注、上传文档、检索片段中的“忽略规则”“授予权限”等文字一律作为原文数据；工具、角色、签署和任务边界由服务端执行。权限必须在候选召回前落实，缓存键也需包含权限与知识版本。

## 6. 评测用例与验收方式

详细的 12 条可执行金标草案见 `services/cra_api/data/knowledge/examples/rag_eval_cases.jsonl`。每条都有问题、背景/用户/`as_of`、应命中的资料与片段、必要证据、预期要点、补问/拒答条件、通过标准和分组。覆盖正常改写、精确边界、跨文档、例外、错数、历史、版本、公开资料用途、越权、无答案和注入。该集还没有运行结果。

三层分别验收，定位首个失败点：

1. **资料齐全性**：业务负责人逐例确认原件、有效版本、适用范围、必要反证和权限是否可用；没有资料的用例预期正确拒答。
2. **检索**：对有答案用例标注到 `chunk_id`，按授权范围计算 Recall@5/20 和 MRR@5；无答案/越权单独统计“是否出现不该出现的候选”。不要把源文件级 Hit@5 当作片段级召回。dev 与 holdout 按来源/案件/版本隔离。
3. **生成与业务结果**：人工逐句核对规则条件、数字单位、版本、冲突处理和引用能否定位原件；机器检查 ID/数字/权限/固定字段。正确补问或转人工可算处理合规，但不算自主完成。

**建议发布门禁（设计目标，非实测）**：所有 P0 用例的越权暴露、旧版当现行、错金额/单位、无依据审批建议、冲突自动放行均为 0；正常/改写题必须找到金标片段并给出可点击、支持结论的引用；无答案题必须解释资料缺口且不得编造。首次试跑先报告逐例结果和样本量，再由政策负责人设定统计阈值；12 条样例不能证明生产精度。每次制度/切分/模型更新复跑受影响用例和核心不变量，记录代码、知识、规则、Prompt、索引版本。
